Lattice Architecture

A complete per-file map of packages/lattice — the polyglot module-boundary enforcement engine, its three faces, and every seam that keeps them honest.

An empty result is a claim, not a shrug. An empty diagnostic list must mean “no violation”, and nothing else.

— AGENTS.md, the invariant everything is judged against

What this package is

@ecoma-io/lattice closes two halves of one gap in Nx monorepos: edges (Nx infers none for Go, Rust, Python) and enforcement (@nx/enforce-module-boundaries reads only JS/TS/Vue, so a Go project’s layer:/scope: tags match no mechanism at all). One analysis behind three faces: an Nx plugin (nx.mjs), a CLI (cli.mjs), and a language server (lsp.mjs).

Plain ESM .mjs with JSDoc — no TypeScript compilation, no build step. Only runtime dependency: smol-toml. Optional peers: nx, vue, @nx/eslint-plugin. Required peer: typescript ≥5 <7. Node ≥22.

The package reproduces all 15 violation types and 8 options of @nx/enforce-module-boundaries over ImportSite records instead of an ESLint AST. Five CLI commands: check, graph, diff, impact, explain. Four exit codes: 0=clean, 1=findings (check only), 2=usage error, 3=no verdict.

Layer knowledge constraints

Each layer may know only what its role grants. Violating these boundaries is how silent bugs enter.

Key constraints that follow from the layering:

  • Analysis never judges. It reports import sites; whether an import is allowed is rules’ question.
  • Rules never read files. Pure function: evaluate(sites, graph, config) → Violation[].
  • Workspace is the only layer allowed to answer “which files.”
  • Providers are the only layer allowed to build a graph.
  • Report renders and decides nothing.
  • Options is the only layer allowed to know what a workspace named its files.

Gaps and known limitations

Production gaps (things that are deliberately missing or deferred)

  • LSP: inline policy objects refused. When lattice.json holds boundaryConfig as an inline policy object (instead of a filename string), the language server refuses to start. The CLI reads inline policies fine; the LSP does not.
  • LSP: ESLint flat-config dialect not supported. Both eslint.config.* and legacy .eslintrc* basenames are refused with a throw. The LSP boundary-config reader does not yet wire eslint-config.mjs’s reader together with revision semantics.
  • LSP: no incremental sync. Full sync only advertised. Incremental sync stays unadvertised until it can be proven correct.
  • LSP: no hover, definition, or other capabilities beyond diagnostics. Deliberately not advertised — a capability is a promise.
  • SARIF: driver has no version/semanticVersion. The header explicitly notes this as a gap. Adding it changes reported output, so it needs a dedicated commit.
  • options.mjs: pluginIsRegistered not consulted. Exported and tested but not yet wired into check’s refusal logic.
  • Ban mechanism: nested paths unreachable in non-JS. isConstraintBanningProject uses npm’s / separator, so use rustshell::window::Manager and import pyshell.window are not caught by the ban. Only the bare crate/module form is. Parity with upstream.
  • Rust: renamed dependencies not followed at source level. dep = { package = "real" } draws a manifest-level edge but source-level resolution uses the local name, producing a failure record rather than a silent miss.
  • Python: unmodelled build backends produce failures. Maturin, scikit-build, etc. are recorded as failures rather than silently assumed external.
  • TypeScript: no realpath. pnpm workspace links resolve as external. Known and documented.
  • Native provider: no tag inferred from package.json. Unlike Nx’s built-in plugin, which synthesizes npm:public/npm:private automatically, the native provider does not. Migrating workspaces must add tags explicitly.
  • Native provider: data.targets names, never runs. "lattice:declared" is a fixed placeholder, never a real executor identity a rule could branch on.
  • Topology: ng-package.json fallback not reproduced. Upstream’s getEntryPoint has this fallback; this engine does not, so Angular secondary entry points declared that way get the strict answer.
  • Conformance: real-tree differential covers TypeScript workspaces only. No public Nx tree with Go/Rust/Python/Vue sources and a non-trivial constraint table under a permissive license was found to pin.

What is NOT a gap

Several things that look like gaps are deliberate design decisions, documented and tested:

  • Static analysis by design. No shelling out to go list/cargo metadata/uv. The graph must compute without language toolchains.
  • No externalNodes emitted. Synthesized on demand in rules/index.mjs instead of declared by providers.
  • One module/crate/package per project root. The modeling assumption for src/graph/; src/analysis/ is deliberately broader (attributes files, not manifests).
  • Analyze.mjs stub throws, not returns empty. A registered language with no analyzer is a missing implementation, not a clean workspace.
  • Malformed go.work / malformed tsconfig paths throw (exit 3). Reading them as empty would silence the check exactly where the data is most broken.
  • Suppression cannot silence a failure. Suppressions filter post-verdict; they cannot skip the checks that make evaluate() throw.
  • The conformance defect ledger (one entry). An exemption-mechanism difference (boundarySuppressions vs. eslint-disable), not a rule this engine cannot reproduce.

Parse limits (pinned, not gaps)

  • Go: block imports read to first ); commented-out imports inside a block still count; no raw string literal support.
  • Rust: use read only at start of line; brace-group use records a failure; renamed package = not followed at source level.
  • Python: per-line matching (no continuation lines); triple-quoted strings may produce spurious records; TYPE_CHECKING imports stay kind: "static".
  • TypeScript: no realpath; require(x) with a local function named require produces spurious records; non-literal import() arguments record as unresolvable + failure.
